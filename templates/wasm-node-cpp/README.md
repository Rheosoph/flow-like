# Flow-Like WASM Node Template (C++)

This template builds custom WASM **Component Model** nodes using C++ with
wasi-sdk and wit-bindgen-c. The Component Model gives you full WASI Preview 2
support including TCP/UDP/DNS via WASI sockets.

## Prerequisites

- [Rust toolchain](https://rustup.rs/) (for installing wasm-tools & wit-bindgen)
- CMake 3.14+
- [mise](https://mise.jdx.dev/) (optional — automates setup & build)

All other dependencies (wasi-sdk, wasm-tools, wit-bindgen) are installed
automatically by `mise run setup`.

## Quick Start

```bash
# 1. Install tooling
mise run setup

# 2. Build the WASM component
mise run build

# 3. Find the output
ls node.wasm
```

Or manually:

```bash
# Install wasi-sdk, wasm-tools, wit-bindgen (see mise.toml for details)

# Generate C bindings from WIT
wit-bindgen c --world flow-like-node --out-dir gen wit/flow-like-node.wit

# Build core module with wasi-sdk
export WASI_SDK_PATH="$HOME/.wasi-sdk/wasi-sdk-25.0"
mkdir -p build && cd build
cmake .. -DCMAKE_TOOLCHAIN_FILE="$WASI_SDK_PATH/share/cmake/wasi-sdk.cmake"
make
cd ..

# Create the final WASM component
wasm-tools component new build/node.wasm -o node.wasm
```

## Creating Your Node

### 1. Define the Node

Edit `src/node.cpp` and modify `build_definition()`:

```cpp
static NodeDefinition build_definition() {
    NodeDefinition def;
    def.name          = "my_node";
    def.friendly_name = "My Node";
    def.description   = "Does something useful";
    def.category      = "Custom/WASM";

    def.add_pin(PinDefinition::input("exec", "Execute", "Trigger", "Exec"));
    def.add_pin(PinDefinition::input("value", "Value", "Input value", "String")
        .with_default("\"\""));

    def.add_pin(PinDefinition::output("exec_out", "Done", "Complete", "Exec"));
    def.add_pin(PinDefinition::output("result", "Result", "Output value", "String"));

    return def;
}
```

### 2. Implement the Logic

Modify `handle_run()`:

```cpp
static ExecutionResult handle_run(Context& ctx) {
    std::string value = ctx.get_string("value");

    std::string result = do_something(value);

    ctx.set_output("result", json_quote(result));
    return ctx.success();
}
```

### 3. Build & Test

```bash
mise run build
```

## Available Pin Types

| Type | String Literal | Description |
|------|---------------|-------------|
| Exec | `"Exec"` | Execution flow trigger |
| String | `"String"` | Text / JSON string |
| I64 | `"I64"` | 64-bit integer |
| F64 | `"F64"` | 64-bit float |
| Bool | `"Bool"` | Boolean |
| Generic | `"Generic"` | Any serialisable JSON value |
| Bytes | `"Bytes"` | Binary data (base64) |

## Context API

```cpp
// Read inputs (via WIT pins interface)
std::string s = ctx.get_string("name", "default");
int64_t n     = ctx.get_i64("count", 0);
double d      = ctx.get_f64("ratio", 1.0);
bool b        = ctx.get_bool("flag", false);

// Write outputs (values must be valid JSON)
ctx.set_output("text", json_quote("hello"));
ctx.set_output("count", std::to_string(42));
ctx.set_output("flag", "true");

// Exec flow
ctx.activate_exec("exec_out");

// Logging
ctx.debug("verbose info");
ctx.info("normal info");
ctx.warn("warning");
ctx.error("error");

// Streaming
ctx.stream_text("progress update");
ctx.stream_event("progress", "{\"pct\":0.5}");

// Finalise
return ctx.success();   // activates exec_out + finish
return ctx.fail("msg"); // sets error + finish
```

## WIT Host Imports

All host functions are generated by wit-bindgen-c from `wit/flow-like-node.wit`.
The naming convention is `flow_like_node_<interface>_<function>`, for example:

```cpp
// Logging
flow_like_node_logging_log(level, &message);

// Pins
flow_like_node_pins_get_input(&name, &result);
flow_like_node_pins_set_output(&name, &value);
flow_like_node_pins_activate_exec(&name);

// Variables
flow_like_node_variables_get_var(&name, &result);
flow_like_node_variables_set_var(&name, &value);

// Cache
flow_like_node_cache_cache_get(&key, &result);
flow_like_node_cache_cache_set(&key, &value);

// Metadata
flow_like_node_metadata_get_node_id(&result);
flow_like_node_metadata_is_streaming();

// HTTP
flow_like_node_http_request(method, &url, &headers, &body, &result);

// Storage
flow_like_node_storage_read_file(&path, &result);
flow_like_node_storage_write_file(&path, &data);
```

## Networking

With the Component Model (WASI Preview 2), you get native socket support.
For simple HTTP requests use the host-provided `http.request` import (see
`examples/http_request.cpp`). For advanced networking (raw TCP/UDP), the
WASI sockets interfaces are available through the component model.

## Build Tips

- Use `-O2` or `-Os` for smaller WASM output.
- Exceptions and RTTI are disabled by default (`-fno-exceptions -fno-rtti`).
- No `alloc`/`dealloc` exports needed — the Component Model canonical ABI handles memory.

## Troubleshooting

| Issue | Solution |
|-------|----------|
| `wit-bindgen` not found | Run `mise run setup` or `cargo install wit-bindgen-cli@0.53.1` |
| `wasm-tools` not found | Run `mise run setup` or `cargo install wasm-tools` |
| CMake can't find toolchain | Ensure `$WASI_SDK_PATH` is set correctly |
| Missing `gen/flow_like_node.h` | Run `mise run generate` before building |
| `wasm-tools component new` fails | Ensure the core module was built with `-mexec-model=reactor` |
| WASM too large | Enable `-Os` optimisation, strip debug info |
