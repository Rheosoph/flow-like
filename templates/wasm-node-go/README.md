# Flow-Like WASM Node Template (Go) — Component Model

This template builds a WASM **Component** (WASI Preview 2) using Go with TinyGo 0.40+. Component Model enables direct TCP/UDP/DNS via WASI sockets — no special host functions needed.

## Prerequisites

- Go 1.22+
- TinyGo 0.40+ (managed via mise)
- wit-bindgen-go (installed automatically by `mise run setup`)

## Quick Start

```bash
mise run build
cp node.wasm /path/to/flow-like/wasm-nodes/
```

Or manually:

```bash
go install go.bytecodealliance.org/cmd/wit-bindgen-go@latest
wit-bindgen-go generate --world flow-like-node --out gen ./wit
go mod tidy
tinygo build -o node.wasm -target wasip2 -no-debug ./
```

## Creating Your Node

### 1. Define the Node

Edit `main.go` and modify `buildDefinition()`:

```go
func buildDefinition() NodeDefinition {
    def := NewNodeDefinition(
        "my_node", "My Node", "Does something useful", "Custom/WASM",
    )
    def.AddPin(InputExecPin("exec"))
    def.AddPin(InputPin("value", "Value", "Input value", "String"))
    def.AddPin(OutputExecPin("exec_out"))
    def.AddPin(OutputPin("result", "Result", "Output", "String"))
    return def
}
```

### 2. Implement the Logic

Modify `handleRun()`:

```go
func handleRun(ctx *Context) ExecutionResult {
    value := ctx.GetString("value", "")
    // ... your logic ...
    ctx.SetOutput("result", jsonQuote(value))
    return ctx.Success()
}
```

### 3. Build

```bash
mise run build
```

## Available Pin Types

| Type | Description |
|------|-------------|
| `Exec` | Execution flow pin |
| `String` | Text value |
| `I64` | 64-bit integer |
| `F64` | 64-bit float |
| `Bool` | Boolean value |
| `Generic` | Any JSON-serializable value |
| `Bytes` | Raw bytes |
| `Date` | ISO 8601 date-time string |
| `PathBuf` | File system path |

## Context Methods

| Method | Description |
|--------|-------------|
| `ctx.GetString(name, default)` | Get string input |
| `ctx.GetI64(name, default)` | Get integer input |
| `ctx.GetF64(name, default)` | Get float input |
| `ctx.GetBool(name, default)` | Get boolean input |
| `ctx.SetOutput(name, value)` | Set output value |
| `ctx.ActivateExec(pinName)` | Activate an exec output |
| `ctx.Success()` | Finish with success (activates `exec_out`) |
| `ctx.Fail(error)` | Finish with error |
| `ctx.Debug(msg)` | Log debug message |
| `ctx.Info(msg)` | Log info message |
| `ctx.Warn(msg)` | Log warning |

| `ctx.StreamText(text)` | Stream text to client |
| `ctx.StreamEvent(type, data)` | Emit named stream event |
| `ctx.GetVar(name)` | Get a variable |

## Component Model Advantages

With Component Model (`wasip2`), you get:
- **Direct TCP/UDP/DNS** via `net.Dial`, `net.Listen`, etc.
- **String ABI** — no manual `alloc`/`dealloc` memory management
- **WIT-defined interfaces** — type-safe host imports generated from `wit/flow-like-node.wit`
- **WASI Preview 2** capabilities (clocks, random, filesystem, sockets)

## Generated Code

The `gen/` directory is created by `wit-bindgen-go generate` and is not committed. It contains:
- **Import wrappers** for each WIT interface (`gen/flow_like/node/logging/`, `gen/flow_like/node/pins/`, etc.)
- **Export infrastructure** for the world's exported functions

The generated interface names derive from the WIT world name `flow-like-node`. If your wit-bindgen-go version uses different naming, update the `init()` call in `main.go`.

## Troubleshooting

- **"cannot find package gen/..."**: Run `mise run generate` (or `wit-bindgen-go generate ...`) first to create the bindings
- **"gen.SetFlowLikeNode undefined"**: The generated setter name differs — check `gen/*.go` for the actual function name
- **Large binary**: Use `-no-debug` and consider `-opt=z` for size optimization
- **Missing main()**: TinyGo requires `func main() {}` even if empty
