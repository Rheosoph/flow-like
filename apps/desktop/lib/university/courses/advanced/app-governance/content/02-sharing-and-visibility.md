| Visibility | Audience |
| --- | --- |
| Private | Your account |
| Prototype | Invited collaborators |
| Public Request | Store visitors may request access |
| Public | Store visitors may join |

For this course, Prototype is sufficient. Test the invitation and access matrix without requesting public visibility.

A public transition uses the publication review workflow. Before requesting one for a real app, identify the audience, public routes, authentication, default role, retained data, pinned versions and responsible owner. If the platform enables an AI assessment gate, confirm the current assessment is eligible before submitting. A publication approval does not pin a Flow or grant a member's operation permissions.

Practice: write a two-sentence visibility decision for the synthetic app. Name its audience and explain why its default role is appropriate. Then consider a forwarded invitation link: list exactly which operations a new member would gain under that role.

Completion: the decision matches the tested access. Do not broaden visibility as part of this exercise.
