## Creating a Client

Choose one authentication method. The client adds `/api/v1` to the base URL,
so use the API origin without that suffix.

```typescript title="environment-client.ts"
import { FlowLikeClient } from "@flow-like/sdk";

// FLOW_LIKE_BASE_URL plus FLOW_LIKE_PAT or FLOW_LIKE_API_KEY
const client = new FlowLikeClient();
```

For an explicit Personal Access Token:

```typescript title="pat-client.ts"
import { FlowLikeClient } from "@flow-like/sdk";

const client = new FlowLikeClient({
  baseUrl: "https://api.flow-like.com",
  pat: "pat_myid.mysecret",
});
```

For an App API key:

```typescript title="api-key-client.ts"
import { FlowLikeClient } from "@flow-like/sdk";

const client = new FlowLikeClient({
  baseUrl: "https://api.flow-like.com",
  apiKey: "flk_appid.keyid.secret",
});
```

Replace the sample credentials with values from your secret configuration. The
Node.js client accepts `pat` or `apiKey`; the `token` convenience parameter is
available in the Python client and the standalone LangChain wrappers.

## Workflows

### Trigger a workflow (streaming)

Returns a Server-Sent Events stream:

```typescript
for await (const event of client.triggerWorkflow(
  "app-id",
  "board-id",
  "start-node-id",
  { key: "value" },
)) {
  console.log(event.data);
}
```

### Trigger a workflow (async)

Returns immediately with a run ID for polling:

```typescript
const result = await client.triggerWorkflowAsync(
  "app-id",
  "board-id",
  "start-node-id",
  { key: "value" },
);
console.log(result.run_id, result.poll_token);
```

### Trigger an event

```typescript
// Streaming
for await (const event of client.triggerEvent("app-id", "event-id", { key: "value" })) {
  console.log(event.data);
}

// Async
const result = await client.triggerEventAsync("app-id", "event-id", { key: "value" });
```

## Execution Monitoring

```typescript
// Check run status
const status = await client.getRunStatus("run-id");
console.log(status.status); // For example, "Running", "Completed", or "Failed"

// Poll for execution events
const poll = await client.pollExecution("poll-token", {
  afterSequence: -1,
  timeout: 30,
});
for (const event of poll.events) {
  console.log(event);
}
```

The poll token comes from an async invocation. The SDK sends it as Bearer
authorization without the client's PAT or API key. Start with cursor `-1` so
the first event, sequence `0`, is included; pass `poll.lastSequence` on the
next call. A completed run can still have additional event pages to read.

For stored run history and node logs:

```typescript
const runs = await client.listRuns("app-id", "board-id", { limit: 20 });
const logs = await client.getRunLogs("app-id", "board-id", "run-id", {
  query: { levels: [2, 3, 4] },
  offset: 0,
  limit: 50,
});
const summary = await client.getRunSummary("app-id", "board-id", "run-id");
await client.cancelRun("running-run-id");
```

`getRunPayload()` reads the captured input for a stored run when available.
These methods read the hub's execution history. Device-local structured logs
use the encrypted [device log viewer](/devices/deployments/#read-workflow-execution-logs).

## Publish and release a workflow

Publishing creates a board version only when the saved workflow has changed.
Set the Event's `board_version` to the returned tuple to make its next invocation
use that version.

```typescript
const published = await client.publishBoardIfChanged("app-id", "board-id");
const event = await client.getEvent("app-id", "event-id");
await client.upsertEvent("app-id", "event-id", {
  ...event,
  board_version: published.version,
});
```

Use `getBoardVersionCurrent()` to inspect the saved board's publication state.
Event management also includes listing, deletion, versions, validation, setup,
and restore. Complex management payloads follow the backend JSON contract.

## File Management

```typescript
// List files in an app's storage
const files = await client.listFiles("app-id", { prefix: "uploads/" });

// Upload a file
await client.uploadFile("app-id", myFile);

// Download a file
const response = await client.downloadFile("app-id", "path/to/file.pdf");
const content = await response.arrayBuffer();

// Delete a file
await client.deleteFile("app-id", "path/to/file.pdf");
```

For a `Buffer` or unnamed `Blob`, pass `{ key: "uploads/file.pdf" }` to
`uploadFile()`. Upload and download helpers obtain a signed URL, then transfer
the bytes without forwarding platform credentials. Use `getUploadUrls()` or
`getDownloadUrls()` when another process should perform the transfer. Set
`scope: "user"` for user storage. `presignData()` returns scoped storage
credentials rather than a file download URL.

## Database / LanceDB

### Credentials

```typescript
// Get resolved credentials (uri + storageOptions ready for LanceDB)
const info = await client.getDbCredentials("app-id", "_default", "read");
console.log(info.uri, info.storageOptions);

// Get raw presign response (shared_credentials enum, db_path, etc.)
const raw = await client.getDbCredentialsRaw("app-id", "_default", "write");
```

### Tables

```typescript
// List tables
const tables = await client.listTables("app-id");

// Query a table with SQL-like filter
const rows = await client.queryTable("app-id", "my-table", {
  filter: "age > 25",
  limit: 10,
});
```

### LanceDB Connection

<Aside type="note">
  Requires `@lancedb/lancedb` as a peer dependency.
</Aside>

```typescript
// Returns a ready-to-use LanceDB Connection object
const db = await client.createLanceConnection("app-id", "write");

// Now use it with the LanceDB API
const table = await db.openTable("my-embeddings");
const results = await table.search([0.1, 0.2, 0.3]).limit(10).toArray();
```

For LanceDB's full connection and table types, import the factory from
`@flow-like/sdk/lancedb` and call `createLanceConnection(client, appId, accessMode, scope)`.
The core client exposes common operations without requiring optional peer types.

The `accessMode` parameter controls whether you get read-only or read-write credentials:
- `"read"` (default): read-only access
- `"write"`: full read-write access

## Chat Completions

Select a model whose `api_surface` is `ChatCompletions`. Models without that
field use the same surface for compatibility. The API returns HTTP 400 if the
selected model requires a different surface.

```typescript title="chat-completions.ts"
const models = await client.listLlms();
const model = models.find(
  (item) => (item.api_surface ?? "ChatCompletions") === "ChatCompletions",
);
if (!model) throw new Error("This hub has no Chat Completions model.");

const result = await client.chatCompletions(
  [{ role: "user", content: "Explain quantum computing in one sentence." }],
  model.bit_id,
  { temperature: 0.7, max_tokens: 200 },
);
console.log(result);
```

### Streaming

```typescript
for await (const chunk of client.chatCompletionsStream(
  [{ role: "user", content: "Hello!" }],
  model.bit_id,
)) {
  process.stdout.write(chunk.data);
}
```

## Responses

Use `responses()` for a model whose `api_surface` is `Responses`. Its input
and output follow the Responses schema, with `input` and `output` in place of
Chat Completions messages and choices.

```typescript title="responses.ts"
const models = await client.listLlms();
const model = models.find((item) => item.api_surface === "Responses");
if (!model) throw new Error("This hub has no Responses model.");

const result = await client.responses(
  "Explain quantum computing in one sentence.",
  model.bit_id,
  { max_output_tokens: 200 },
);
console.log(result.output);
```

For streaming, iterate `client.responsesStream(input, model.bit_id)` as an
async iterable. Each chunk contains the event name and its JSON `data` string.
Keep the event type when handling progress and final output.

## Embeddings

Use `listEmbeddingModels()` to discover available embedding model `bit_id` values.

```typescript
const result = await client.embed("bit-id-for-embedding", [
  "Hello world",
  "Goodbye world",
]);
console.log(result.embeddings); // number[][]
```

For media, select a compatible model such as Gemma 2
(`i6un3u7arw9mt59xzpc6rmzm`). `embed()` also accepts structured `text`, `image`,
`audio`, and `video` inputs, or a mixed array that returns one vector per item.
A `multimodal` input combines text and up to one file per modality into one vector:

```typescript
const signedVideoUrl =
  "https://storage.googleapis.com/bucket/demo.mp4?X-Goog-Signature=...";
const result = await client.embed("i6un3u7arw9mt59xzpc6rmzm", {
  type: "multimodal",
  text: "A product demonstration: <|image|> <|audio|> <|video|>",
  image: "https://example.com/product.jpg",
  audio: "https://example.com/narration.wav",
  video: signedVideoUrl,
}, { embed_type: "document" });
console.log(result.embeddings[0]); // One 768-dimensional vector
```

Replace the example URLs with final download URLs. Media fields take a string
containing a public or signed HTTP(S) URL, a base64 data URL, or raw base64. The SDK
forwards signed URLs with their query parameters unchanged. Keep them valid through
the worker's download, including cold starts. Redirects, private addresses, and local
paths are rejected. Video contributes sampled frames; provide its soundtrack in
`audio` to include it in the combined embedding.

## Model Discovery

```typescript
// List all remotely-available LLMs
const llms = await client.listLlms();
for (const m of llms) {
  console.log(m.bit_id, m.name, m.api_surface, m.context_length);
}

// List all remotely-available embedding models
const embeddings = await client.listEmbeddingModels();
for (const m of embeddings) {
  console.log(m.bit_id, m.name, m.vector_length);
}

// Search all bits by keyword
const bits = await client.searchBits({ search: "llama", bit_types: ["Llm"] });

// Get a specific bit by ID
const bit = await client.getBit("some-bit-id");
```

Each model returns a `ModelInfo` object:

```typescript
interface ModelInfo {
  bit_id: string;
  name: string;
  description: string;
  provider_name?: string;
  api_surface?: "ChatCompletions" | "Responses";
  model_id?: string;
  context_length?: number;  // LLMs only
  vector_length?: number;    // Embeddings only
  languages?: string[];
  tags: string[];
}
```

## LangChain Integration

<Aside type="tip">
  Requires `@langchain/core` as a peer dependency: `npm install @langchain/core`
</Aside>

### Factory methods (recommended)

Create LangChain-compatible models from your existing client:

```typescript
// Chat model
const chatModel = await client.asLangChainChat("your-model-bit-id", {
  temperature: 0.7,
  maxTokens: 1024,
});

// Embeddings
const embeddings = await client.asLangChainEmbeddings("your-embedding-bit-id");
```

The core factories expose common model operations. For LangChain's full Runnable
types, including chain composition, use the factories from `@flow-like/sdk/langchain`.

### Standalone usage

```typescript
import { FlowLikeChatModel, FlowLikeEmbeddings } from "@flow-like/sdk/langchain";

const chatModel = new FlowLikeChatModel({
  baseUrl: "https://api.flow-like.com",
  token: "pat_myid.mysecret",
  bitId: "your-model-bit-id",
  temperature: 0.7,
});

const embeddings = new FlowLikeEmbeddings({
  baseUrl: "https://api.flow-like.com",
  token: "pat_myid.mysecret",
  bitId: "your-embedding-bit-id",
});
```

### With LangChain chains

```typescript
import { ChatPromptTemplate } from "@langchain/core/prompts";
import { StringOutputParser } from "@langchain/core/output_parsers";
import { asLangChainChat } from "@flow-like/sdk/langchain";

const chatModel = await asLangChainChat(client, "your-model-bit-id");

const chain = ChatPromptTemplate
  .fromMessages([
    ["system", "You are a helpful assistant."],
    ["human", "{input}"],
  ])
  .pipe(chatModel)
  .pipe(new StringOutputParser());

const response = await chain.invoke({ input: "What is Flow-Like?" });
```

### RAG with LangChain

```typescript
const embeddings = await client.asLangChainEmbeddings("your-embedding-bit-id");

// Use with any LangChain vector store
const vectors = await embeddings.embedDocuments([
  "Flow-Like is a visual workflow engine.",
  "It runs on your device.",
]);
const queryVector = await embeddings.embedQuery("What runs locally?");
```
