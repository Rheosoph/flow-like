Flow-Like A2UI surfaces are normalized component trees. Each component has a
stable ID, a lower-camel-case `type`, typed properties, optional styles, and
references to its children. This is the same contract used by the visual
builders, FlowPilot, Pages, and Widgets. For visual authoring, start with
[Create Pages](/apps/pages/) or [Create Widgets](/apps/widgets/).

<Aside type="caution" title="Use the current contract">
  Component types are lower camel case (`textField`, not `TextField`), properties
  live directly inside `component`, and children reference component IDs. The old
  `{ "type": "Button", "props": { ... } }` shape is not the runtime contract.
</Aside>

## Surface shape

A generated or imported surface uses one root ID and a flat component array:

```json
{
  "rootComponentId": "root",
  "canvasSettings": {
    "padding": "24px"
  },
  "components": [
    {
      "id": "root",
      "style": {
        "className": "min-h-full bg-background text-foreground"
      },
      "component": {
        "type": "column",
        "gap": { "literalString": "16px" },
        "children": {
          "explicitList": ["title", "open-dashboard"]
        }
      }
    },
    {
      "id": "title",
      "component": {
        "type": "text",
        "content": { "literalString": "Operations dashboard" },
        "variant": { "literalString": "heading" },
        "size": { "literalString": "2xl" },
        "weight": { "literalString": "bold" }
      }
    },
    {
      "id": "open-dashboard",
      "component": {
        "type": "button",
        "label": { "literalString": "Open dashboard" },
        "variant": { "literalString": "default" },
        "actions": [
          {
            "name": "navigate_page",
            "context": { "route": "/dashboard" }
          }
        ]
      }
    }
  ],
  "dataModel": []
}
```

The visual builders maintain this structure for you. Use the JSON contract
directly when generating a complete surface with FlowPilot or another coding
agent.

## Shared value types

Most visible component properties use `BoundValue`, even when their value is
currently static.

| Value | JSON shape |
| --- | --- |
| String | `{ "literalString": "Hello" }` |
| Number | `{ "literalNumber": 42 }` |
| Boolean | `{ "literalBool": true }` |
| Select options | `{ "literalOptions": [{ "value": "open", "label": "Open" }] }` |
| Arbitrary JSON | `{ "literalJson": "{\"key\":\"value\"}" }` |
| Data binding | `{ "path": "$.data.customer.name", "defaultValue": "Customer" }` |

Do not substitute raw strings or numbers where a component property expects a
`BoundValue`.

### Children

Use an explicit list for a known component tree:

```json
{
  "children": {
    "explicitList": ["heading", "description", "actions"]
  }
}
```

Template children are available for data-driven repetition:

```json
{
  "children": {
    "template": {
      "dataPath": "$.data.items",
      "itemIdPath": "$.id",
      "templateComponentId": "item-template"
    }
  }
}
```

For a reusable card, row, or repeated interaction pattern, prefer a
`widgetInstance`. A Widget owns its own component tree, exposed properties,
and named actions.

### Actions

Actions are an array inside the interactive component:

```json
{
  "type": "button",
  "label": { "literalString": "Approve" },
  "actions": [
    {
      "name": "workflow_event",
      "context": {
        "nodeId": "board-event-node-id"
      }
    }
  ]
}
```

Use one board Event for each distinct purpose. Page actions use the fixed
`workflow_event` name and identify the selected Event with `context.nodeId`.
The Event handler reads live input state with nodes such as **Get Element
Value** or **Get File Input Files**; typed values should not be copied into the
action context.

The current action contracts are:

| Action | Context |
| --- | --- |
| `workflow_event` | `nodeId`; the builder also includes the owning `appId` and `boardId` |
| `widget_event` | `actionId`; resolved through the Widget instance's action binding |
| `navigate_page` | `route` plus optional `queryParams` |
| `external_link` | `url` |

For Widgets, declare the action ID in the Widget definition and bind that ID
when the Widget is instantiated. There are no `onClick`, `onChange`,
`updateData`, `openModal`, or `closeModal` action objects in the current
component contract. A host may receive an otherwise unknown action name as a
generic `userAction`, but that fallback does not execute a workflow by itself.

## File preview and editing

Use `filePreview` to open a file from `src` or its alias `url`. The component
selects a viewer from the filename, MIME type, or URL extension. Office files
use the same WebAssembly (WASM) viewers as Storage. PDFs, images, audio, and
video keep their usual preview until editing is enabled. Plain text and code
remain preview-only.

The Office viewers support `.docx`, `.pptx`, `.potx`, `.ppsx`, and spreadsheet
formats including `.xlsx`, `.xls`, `.xlsb`, `.ods`, `.csv`, and `.tsv`. Legacy
`.ppt` and `.doc` are unsupported. Other formats follow the Storage editor
registry. These editors are experimental: importing and exporting a file may
change formatting or omit unsupported features.

All properties below use `BoundValue`:

| Property | Contract |
| --- | --- |
| `src`, `url` | Source URL. `url` is an alias for `src`. |
| `filename`, `mimeType` | File metadata used to choose the viewer. Supply a filename when a signed URL has no useful extension. |
| `fileType` | Optional override: `pdf`, `image`, `video`, `audio`, `code`, `text`, or `document`. `document` asks the WASM registry to select a viewer from the metadata. |
| `editable` | Enable the matching WASM editor. Defaults to `false`. Requires an exact `save` event handler containing `workflow_event` or `widget_event` actions. |
| `initialEditing` | Start in edit mode when `editable` is enabled. Defaults to `false`. |
| `value` | Last exported file metadata. A path binding is updated before the save workflow runs. It does not change the source URL. |

```json
{
  "type": "filePreview",
  "src": { "path": "$.data.presentation.url" },
  "filename": { "literalString": "presentation.pptx" },
  "editable": { "literalBool": true },
  "initialEditing": { "literalBool": false },
  "value": { "path": "$.data.presentation.exportedFile" },
  "eventHandlers": {
    "save": [
      {
        "name": "workflow_event",
        "context": { "nodeId": "save-presentation-event-node-id" }
      }
    ]
  }
}
```

Saving exports the edited file and uploads it to backend temporary storage,
using the same upload path as chat attachments. This always creates a new
temporary file, even when the save workflow runs locally. The component never
overwrites the original file.

Use **File Editor** (`fileEditor`) when the page creates documents. Select an
editor in the builder, optionally supply `src` or `url`, and attach a **Save**
workflow in the Actions tab. Without a source, the selected editor creates a new
document. With a source, it opens that file. The full editing workspace requires
the Save workflow; an empty editor shows a setup prompt until it is configured.
`editable` and `initialEditing` default to `true` on this component.

```json
{
  "type": "fileEditor",
  "editor": { "literalString": "solidcraft" },
  "filename": { "literalString": "New model.solidcraft" },
  "value": { "path": "$.data.model.exportedFile" },
  "eventHandlers": {
    "save": [
      {
        "name": "workflow_event",
        "context": { "nodeId": "save-model-event-node-id" }
      }
    ]
  }
}
```

The `editor` value selects `wordcraft`, `pdfcraft`, `deckcraft`, `gridcraft`,
`vectorcraft`, `photocraft`, `soundcraft`, `filmcraft`, `designcraft`, `cadcraft`,
or `solidcraft`. Use `solidcraft` for 3D models and `cadcraft` for DXF drawings.
Omit `filename` to use the selected editor's default name and native format.
New video projects use `.fcproj`; projects that depend on separate media files
need those files and cannot open as standalone inputs here.

The `save` event carries the new URL as `url` and `signedUrls`. Both are
strings, following the single-file input convention.
It also carries exported metadata as both `file` and `value`, plus `src` for
the original source. File metadata contains `name`, `size`, `type`, `url`,
and `backendUrl`. The workflow decides how to use `file.url` or copy its
contents to permanent storage. The workflow can also read the metadata with
**Get Element Value**. A temporary upload alone does not persist the document
at a permanent destination.

Some editors convert formats: `.potx` and `.ppsx` export as `.pptx`,
while `.xls`, `.xlsb`, and `.ods` export as `.xlsx`. FreeCAD `.FCStd` and Rhino
`.3dm` open in `solidcraft` and export as `.solidcraft`, preserving imported
geometry without the original feature history. InDesign `.indd` and `.indt`
open in `designcraft` and export as `.designcraft`. PhotoCraft also imports
XCF, XPM and DICOM into `.pcraft` projects, and reads and writes DDS, DPX,
Cineon and IFF images. VectorCraft imports JPEG 2000 images into `.vectorcraft`
documents. These formats work in both components. Supply `filename`
when a download URL does not identify the file's extension.

SolidCraft saves require version 0.30 or later. Use the exported filename
and MIME type when choosing the destination.

Both components use the same save events. For a new document, `src` in the event
context is an empty string.

To let an agent use the open editor, target the `filePreview` or `fileEditor` with **Get Element**
and connect its **Element** output to **Editor Element** on **Register Editor MCP
Tools**. You can also select the component directly in the **Editor Element**
picker, or copy **Agent target** from the editor toolbar, paste it into the
picker's search field, and choose the matching element or **Use reference**.
Run the flow in the same window as the editor. The agent uses the open draft;
**Save** still runs the configured `save` workflow. See
[Control an open editor with an agent](/apps/storage/#control-an-open-editor-with-an-agent)
for setup and editor-loading requirements.

| Event | Payload and timing |
| --- | --- |
| `save` | `url`, `signedUrls`, `file`, `value`, and original `src`. Runs after export and temporary backend upload. All configured save workflows must succeed before the editor clears its unsaved state. |
| `saved` | The same file metadata and source, after the save workflows succeed. |
| `dirtyChange` | `{ "dirty": true }` or `{ "dirty": false }` when the unsaved state changes. |
| `error` | `{ "message": "..." }` when preview, export, upload, or saving fails. A failed save preserves the draft for retry. |

Bind these exact names in `eventHandlers` or the builder's Actions tab. They
do not inherit `*` or the older `actions` array. `saved`, `dirtyChange`, and
`error` are optional notifications.

In the Actions tab, **Create event in flow** creates a **Widget Action Event**
for these file events. Its **Action Context** output has the event's schema:
`save` and `saved` expose file metadata and URLs, `dirtyChange` exposes a
boolean `dirty`, and `error` exposes a string `message`. Every context also
includes `actionId`, `src`, and `filename`. **Event Name** identifies the
event that ran. File events put these fields directly in Action Context.

The workflow schema follows the saved page bindings. Removing a binding
clears its inferred schema; sharing a handler between incompatible or unknown
event shapes gives it a generic context. Existing Simple Event bindings keep
working. Select or create a Widget Action Event to access typed context
fields in the workflow.

## Rich text documents

Use `richText` to edit and display a Plate document. Its `value` is a string
beginning with `plate_json::`. Store the complete string: the version 1 envelope
contains `children`, `discussions`, and `users`, with an optional `documentId`.
It preserves comment bodies, authors, replies, and resolution state alongside
the article. Existing documents containing a node array after the prefix remain
readable. Native `.plate.json` export preserves review metadata; HTML and Markdown
exports represent the article content.

All properties below use `BoundValue`:

| Property | Contract |
| --- | --- |
| `value` | Required document string. Bind it to the document body in surface data. |
| `documentId` | Stable document identity. Changing it opens a separate editing session and cancels pending events from the previous document. |
| `documentRevision` | Server revision as a string or number. Changing it replaces local edits with the supplied `value`, even when that value matches an earlier value. |
| `currentUser` | Reviewer object with `id`, `name`, and optional `avatarUrl`. Without an explicit value, the editor uses the signed-in identity when available. |
| `reviewEnabled` | Enable comments and tracked suggestions for the current user. Defaults to whether an identity is available; this setting does not grant server permissions. |
| `readOnly`, `disabled` | Display the current document without editing. Changing either preserves the current local value. |
| `uploadScope`, `uploadPrefix` | Media storage scope (`app` by default, or `user`) and folder. The default folder is `a2ui/{surfaceId}/{componentId}`. |
| `label`, `helperText`, `error` | Accessible field label, description, and invalid state. `placeholder` appears while the document is empty. |

```json
{
  "type": "richText",
  "value": { "path": "$.data.article.body" },
  "documentId": { "path": "$.data.article.id" },
  "documentRevision": { "path": "$.data.article.revision" },
  "currentUser": { "path": "$.data.reviewer" },
  "label": { "literalString": "Article body" },
  "reviewEnabled": { "literalBool": true }
}
```

Bind the exact `change`, `blur`, `imageUploaded`, or `imageUploadError` event in
the Actions tab. Change events wait for `debounceMs` (600 milliseconds by default,
minimum 100). Leaving the editor flushes a pending change before `blur`; moving
focus among its controls does not commit. Change and blur carry `value` plus
`documentId` and `documentRevision` when supplied. Upload events carry the same
document identity, with media metadata or an error. A server save should compare
the submitted revision before accepting an update. Supplying a new authoritative
revision to the component resets its local draft; it does not merge simultaneous
edits.

## Excalidraw drawings

Use `excalidraw` to load and edit a drawing, then persist its scene through a
workflow. A scene is the Excalidraw JSON representation, including `elements`,
`appState`, and `files`. Keeping all three preserves the drawing's content,
canvas settings, and embedded images.

All properties below use `BoundValue`:

| Property | Contract |
| --- | --- |
| `value` | Scene object or its JSON string. Bind it to surface data to receive edits. Changing the supplied scene replaces the current drawing. |
| `width`, `height` | Canvas dimensions as CSS values. Defaults to `100%` wide and `600px` high. Give the drawing a visible height. |
| `readOnly` | Show the drawing without editing. Defaults to `false`. |
| `theme` | Editor appearance: `light` or `dark`. |
| `autoSave` | Enable autosave when an exact `autoSave` handler is configured. Defaults to `true`. |
| `autoSaveDelayMs` | Idle time after the last content edit before autosave. Defaults to 1500 milliseconds, with a minimum of 100. Each new content edit restarts the timer. |
| `autoSaveMinChanges` | Minimum content changes since loading or the last successful save before autosave can run. Defaults to `1`. |

```json
{
  "type": "excalidraw",
  "value": { "path": "$.data.drawing" },
  "width": { "literalString": "100%" },
  "height": { "literalString": "600px" },
  "autoSave": { "literalBool": true },
  "autoSaveDelayMs": { "literalNumber": 2000 },
  "autoSaveMinChanges": { "literalNumber": 2 },
  "eventHandlers": {
    "load": [
      {
        "name": "workflow_event",
        "context": { "nodeId": "drawing-loaded-event-node-id" }
      }
    ],
    "save": [
      {
        "name": "workflow_event",
        "context": { "nodeId": "save-drawing-event-node-id" }
      }
    ],
    "autoSave": [
      {
        "name": "workflow_event",
        "context": { "nodeId": "autosave-drawing-event-node-id" }
      }
    ]
  }
}
```

Set `$.data.drawing` to a loaded scene before opening the editor, or update it
from a workflow to replace the drawing later. A new empty scene can be
`{ "type": "excalidraw", "version": 2, "source": "flow-like", "elements": [], "appState": {}, "files": {} }`.
The `load` event reports an applied scene; the `value` property supplies it.
The **Set Excalidraw Scene** node (`ui.setExcalidrawScene`) accepts a typed scene
and replaces the drawing, including when reloading the original scene after local edits.

The editor updates a path-bound `value` as content changes. These updates alone
do not persist the drawing outside surface data. Configure `save` and
`autoSave` workflows to store the scene at the destination your app uses.

| Event | Typed Action Context and timing |
| --- | --- |
| `load` | `actionId`, `value`, and `scene` after a supplied scene is loaded. `value` and `scene` contain the same scene object. |
| `save` | `actionId`, `value`, `scene`, and `changeCount` when the user selects Save or presses Ctrl/Cmd+S in the editor. |
| `autoSave` | The same fields as `save`, after the minimum change count and idle delay are both satisfied. |
| `dirtyChange` | `actionId` and boolean `dirty` when unsaved content appears or clears. |
| `error` | `actionId`, string `message`, and `operation` when loading or saving fails. |

Scene loading, selection, panning, and zooming do not count toward autosave.
`changeCount` counts content changes, which may include several updates during
one drawing gesture. Set the threshold to `1` to save even a single edit after
the user pauses. A higher threshold leaves smaller edits pending until the
user makes enough changes or saves manually.

Saving clears the submitted changes only after every configured save action
succeeds. New edits made while saving remain pending. A failed save keeps the
drawing dirty and reports an error; the user can retry with Save. Manual saving
without a `save` handler also reports an error.

Bind these exact event names in `eventHandlers` or the builder's Actions tab.
They do not inherit `*` or the older `actions` array. In the Actions tab,
**Create event in flow** creates a **Widget Action Event** with the selected
event's schema on its **Action Context** output. Read the scene fields directly
from that context. **Event Name** identifies which event ran. A workflow shared
by incompatible event schemas receives a generic context, so use separate
events when you need each event's typed fields.

## Styling

`style` belongs beside `component` in each component record:

```json
{
  "id": "summary-card",
  "style": {
    "className": "rounded-xl border border-border bg-card p-6 text-card-foreground",
    "shadow": {
      "x": "0",
      "y": "8px",
      "blur": "24px",
      "color": "rgb(0 0 0 / 0.12)"
    }
  },
  "component": {
    "type": "card",
    "title": { "literalString": "Summary" }
  }
}
```

Prefer semantic theme classes such as `bg-background`, `bg-card`,
`text-foreground`, `text-muted-foreground`, and `border-border`. They adapt to
light and dark mode without duplicating color rules.

Structured style fields cover background, border, shadow, spacing, sizing,
position, transform, overflow, typography, visibility, and responsive
overrides.

## Device location

Enable `showLocate` on a `geoMap` to show **Find my location**. The button reads
one foreground location fix using the native provider on supported Apple devices
or the browser location provider. It does not start tracking when the map renders.
The editing canvas disables location acquisition. Closing the Page, hiding it,
or moving the app into the background cancels the request and discards late fixes.

Bind **Location found** in the map's Actions tab to receive these fields:

- `coordinate`: the existing `{latitude, longitude}` object.
- `geometry`: a Geometry Point, `{"type":"Point","coordinates":[longitude,latitude]}`.
- `location`: the full fix, including `geometry`, `latitude`, `longitude`,
  `accuracy`, `timestamp`, `altitude`, `altitudeAccuracy`, `speed`, and `heading`.

Accuracy and altitude are measured in meters, speed in meters per second, and
heading in degrees. Timestamp is Unix time in milliseconds. Unavailable altitude,
altitude accuracy, speed, or heading is `null`. Geometry remains two-dimensional;
altitude belongs in the fix metadata. Existing map Event bindings that read
`coordinate` keep their current shape.

**Location error** carries `code` and `message`, also available under `error`.
The map shows the error beside its controls. This Event runs only when explicitly
bound; older wildcard or legacy actions do not inherit it.

Use **Get Current Location** (`geo.getCurrentLocation`, under **Web / Geo /
Location**) to read location from an Event without a map. Its **High Accuracy**
input defaults to false, **Maximum Age** defaults to zero seconds and accepts up
to 300 seconds, and **Timeout** defaults to 30 seconds with a range of 1 to 120.
Success provides a typed Point on `geometry`, the full fix on `location`, and the
legacy object on `coordinate`. The Error branch provides a structured code and
message. An Event running remotely reads from its invoking device and requests
permission to share that fix with the app.

Connect `geometry` directly to Geometry Point inputs, **Point Distance (Meters)**,
or map update nodes. **Point to Legacy Coordinate** adapts it for existing H3,
routing, and geocoding nodes. Use geodesic distance in meters for geographic
radius checks; planar distance operates in coordinate degrees.

## Live camera

Use `cameraView` when a Page needs to capture a photo, translate visible text,
combine a scene with recent speech, or show detection results over a live preview.
The user starts the camera with its
**Start camera** button. Loading a Page, editing its layout, or calling a node
cannot grant camera access or start the camera.

```json
{
  "id": "inspection-camera",
  "component": {
    "type": "cameraView",
    "label": { "literalString": "Inspection camera" },
    "facingMode": { "literalString": "environment" },
    "intervalMs": { "literalNumber": 2000 },
    "maxWidth": { "literalNumber": 1280 },
    "quality": { "literalNumber": 0.85 },
    "value": { "path": "/camera/frame" },
    "overlays": { "path": "/camera/annotations" }
  }
}
```

Bind the component's **Image captured** or **Interval frame** event in the
builder's Actions tab. These events use the Page's existing Event authorization
and Widget action bindings. Interval capture requires an explicit `frame`
handler. Setting an interval without one never transfers frames. Zero disables
sampling; positive values have a minimum of 250 milliseconds. A tick is skipped
while the previous capture or Event is still running.

After Start, the `value` binding and **Camera ready** event expose `surfaceId`,
`componentId`, `sessionId`, `status`, `audioEnabled`, `audioActive`,
`audioBufferSeconds`, and `audioAvailableMs`. `audioActive` indicates whether the
microphone is recording; `audioAvailableMs` is the recent history available for a
clip. A separate button can read this bound
session and pass its IDs to **Capture Camera Frame**. Every camera command
requires the current session ID, so an earlier Event cannot capture from a camera
that the user has restarted.

The capture payload contains `surfaceId`, `componentId`, `sessionId`, `frameId`,
`capturedAt`, `width`, `height`, and an `image` temporary-storage reference.
It is also available as `frame` and `value` in the action context. The `value`
binding then stores this reference, without image bytes. **Read Camera Image** turns
the frame into the image handle used by OCR and detection nodes. **Capture Camera
Frame** requests a new frame from a camera on the invoking screen, including
when the requesting Event runs remotely.

### Capture recent audio

Set `audioEnabled` to `{ "literalBool": true }` to offer microphone capture.
The user must press **Start camera and microphone** and grant microphone permission.
The default is false, so existing Pages capture video only. `audioBufferSeconds`
sets the amount of recent audio retained in memory, in whole seconds from 1 to
300; the default is 60. Older samples are discarded as new samples arrive.
The buffer stays on the device until an Event explicitly requests a clip.
Automatic frame events transfer images only.

Pass the current `surfaceId`, `componentId`, and `sessionId` to **Capture Camera
Audio** (`ui.captureCameraAudio`) and choose the recent duration to retrieve.
The **Duration** input defaults to 10 seconds. **Capture Camera Input**
(`ui.captureCameraInput`) takes a new frame and a clip from the same active
session before uploading either, so later upload time does
not shift the captured input. Both nodes accept a duration from 0.1 to 300
seconds and return the available portion if the buffer is shorter. Check the
actual **Recorded Duration** output. An empty buffer or an inactive microphone
follows the Error branch.

Both nodes provide **Clip** metadata, **Audio URL**, **Audio Path** when available,
and the actual **Recorded Duration** in seconds. The combined node also provides
**Frame**.
Connect Audio Path to **Speech to Text**, or pass Audio URL to an audio service.
Connect Frame to **Read Camera Image** for OCR or vision analysis. Audio is a
16 kHz, mono, PCM16 WAV file in the Event's configured temporary storage.
Workflows receive file references; audio bytes do not travel in component events.

Clip metadata includes `surfaceId`, `componentId`, `sessionId`, `clipId`,
`capturedAt`, `startedAt`, `endedAt`, `durationMs`, `requestedDurationMs`,
`sampleRate`, `channels`, and an `audio` file reference containing `name`, `type`,
`size`, `url`, and optional `flowPath`. Requests always use the
current session ID and cannot read history from an earlier camera session.

### Annotate and control the preview

**Update Camera Overlays** accepts the original frame and an array of annotations.
Keep that frame attached to the analysis result: the frontend rejects an update
after a newer frame is captured or the camera session ends. Annotation types are
`box`, `text`, `point`, `polygon`, `blur`, and `dim`. Every annotation needs a unique
`id`. Coordinates are normalized to the upright captured image, with `(0, 0)` at
the top left. Boxes and effect regions use `x`, `y`, `width`, and `height`;
polygons use `points`, an array of `[x, y]` pairs. Text uses `x`, `y`, and `text`.

```json
[
  { "id": "object-1", "type": "box", "x": 0.1, "y": 0.2,
    "width": 0.3, "height": 0.4, "text": "Package", "confidence": 0.96 },
  { "id": "translation-1", "type": "text", "x": 0.15, "y": 0.65,
    "text": "Keep upright", "color": "#ffffff", "fontSize": 18 }
]
```

Annotations expire after five seconds by default, configurable from 100 to
60,000 milliseconds. Sending an empty array clears them. For data-bound updates,
wrap the array as `{ sessionId, frameId, overlays, ttlMs }`. `overlayClick` carries
the clicked annotation and its frame identity. Mirroring changes only the
preview; the component aligns annotations with both mirrored previews and
`contain`/`cover` fitting.

The `effects` object supports `grayscale` and `sepia` from 0 to 1, `blur` from 0
to 24 pixels, and `brightness`/`contrast` from 0 to 3. These effects and annotation
regions affect the preview only. Captured images contain the original pixels,
so a preview blur does not redact an image sent to an Event.

**Freeze** pauses the displayed frame for inspection, disables microphone tracks,
and discards audio history. **Resume** returns to live video and re-enables the
already granted microphone tracks with an empty buffer. It never opens a new
microphone permission request. **Stop** releases the camera and microphone and
discards audio history. The **Control Camera** node exposes the same
operations for the session that produced a frame. Camera tracks and interval
scheduling stop when the Page unmounts, the document becomes hidden, the component
or its parent is hidden, or the native host reports an inactive device. Returning
to the screen requires another user start. Late permission replies and analysis
results cannot reopen or modify an ended session. Leaving or hiding the screen
also discards audio history. Browser capture requires HTTPS or localhost and
browser/device permission. Media references use the requesting Event's configured
local or remote temporary storage.

If microphone processing is suspended or interrupted while the screen remains
visible, the session stops and its audio history is discarded. Press **Start
camera and microphone** again to begin a new session.

## Play audio from a workflow

Use **Play Sound** (`ui.playSound`, under **UI → Audio**) to play audio on the
screen that invoked an Event. It works with local and remote Events and does not
require an audio component on the Page. Connect **Text to Speech** or **Capture
Camera Audio** to its **Audio Path** input, or supply an audio download URL through
**Audio URL**. Supply exactly one of these inputs.

**Volume** defaults to 1 and accepts values from 0 to 1; 0 mutes playback. If a
browser cannot apply a requested nonzero volume, the node reports
`unsupported_volume`. Use Volume 1 and the device's volume buttons in that case.
**Timeout** defaults to 300 seconds and accepts 1 to 600 seconds
for the frontend to load the sound, obtain a user tap if needed, and finish
playback. If the browser blocks automatic playback, the screen shows a **Play
sound** action. The workflow waits for that tap within the timeout.

The normal execution output runs after playback finishes. **Duration** reports
the completed sound's length in seconds. Loading errors, rejected playback,
cancellation, and timeout follow the Error branch with a structured code and
message. Navigating to another Page, switching accounts, hiding or backgrounding
the screen, or cancelling the Event stops playback and cancels pending sound
requests. A new sound for the same app stops the previous one. An
Event without an available invoking screen cannot play sound through this node.

Audio travels as a URL or file reference. When a FlowPath needs a temporary copy
for frontend access, the node uses the Event's configured temporary storage and
limits that copy to 32 MiB. It does not send audio bytes through the device
command channel. See the [Play Sound node reference](/nodes/ui/audio/ui-play-sound/)
for its pins.
